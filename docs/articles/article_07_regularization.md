# 机器学习实战 #07：回归问题，从线性回归到正则化

入门系列里我们手写过线性回归——找一组权重，让预测值和真实值的误差平方和最小。那是在干净的玩具数据上。

真实数据会给你出一道新题：当两个特征高度相关时，普通线性回归会算出一组"疯狂"的权重。比如房子的"居住面积"和"地上面积"几乎是一回事，模型可能给第一个 +8000、给第二个 -7000，两个巨大的系数互相抵消。预测看着还行，但这组权重极不稳定——换一批数据重新训练，系数可能完全翻盘。

这就是**多重共线性**，正则化就是来治它的。这一篇讲清楚 Ridge 和 Lasso 到底在约束什么，以及它们在真实房价数据上的实际表现。

## 普通线性回归的麻烦：系数可以无法无天

先回忆线性回归在优化什么。它最小化的是这个东西：

:::formula 线性回归的损失
Loss = Σ(预测值 − 真实值)²
目标：找一组权重 w，让这个误差平方和最小
:::

问题在于，这个目标函数只关心"拟合得准不准"，完全不管"权重本身有多大"。当两个特征高度相关时，模型有无数组权重能达到几乎一样的拟合效果——给 A 一个大正数、给 B 一个大负数，和给两者都一个温和的值，预测结果差不多。优化器会随便挑一组，而它挑中的那组往往系数巨大、方向极端。

系数巨大意味着什么？意味着模型对输入的微小变化极度敏感。面积变动 1 平方米，一个系数是 8000 的模型会让预测价格剧烈波动。这种模型在训练集上看着准，一到新数据就不稳。

正则化的思路很直接：**在"拟合得准"之外，再加一条约束——"权重别太大"。** 把这条约束写进损失函数，让优化器在准确和简洁之间找平衡。

## Ridge 和 Lasso：两种"罚大权重"的方式

正则化在损失函数后面加一个惩罚项，惩罚的对象就是权重的大小。加法不同，就分出了 Ridge 和 Lasso。

**Ridge（L2 正则）** 惩罚的是权重的平方和：

:::formula Ridge 的损失
Loss = Σ(预测值 − 真实值)² + α · Σw²
α 越大，对大权重的惩罚越狠，权重被压得越小
:::

平方项有个特点：权重越大，惩罚增长得越快（平方关系）。所以 Ridge 特别擅长压制那些"疯狂"的大系数——面积 +8000、地上面积 -7000 这种，平方之后惩罚巨大，优化器会主动把它们拉回到温和的水平。但 Ridge 不会把任何系数压到正好 0，它只是整体收缩。

**Lasso（L1 正则）** 惩罚的是权重的绝对值之和：

:::formula Lasso 的损失
Loss = Σ(预测值 − 真实值)² + α · Σ|w|
绝对值惩罚会把不重要的权重直接压到 0
:::

绝对值和平方的区别很微妙但很关键：绝对值惩罚能把一些系数**精确压到 0**，相当于自动做了特征选择——没用的特征，权重直接归零，等于从模型里删掉。这是 Lasso 比 Ridge 多出来的本事。

![L1菱形约束与L2圆形约束的几何直觉](l1_vs_l2.png)

为什么绝对值能把系数压到 0，平方不行？看这张几何图就懂了。正则化相当于把权重限制在一个区域内（L2 是圆、L1 是菱形），同时让误差等高线尽量靠近无约束的最优解。误差等高线和约束区域相切的那个点，就是最终解。L2 的圆没有尖角，切点一般落在非零位置；L1 的菱形有四个尖角正好压在坐标轴上，切点很容易落在尖角处——而落在轴上就意味着某个权重正好是 0。

注意公式里的 α。它是你手动设的旋钮：α=0 就退回普通线性回归（没有惩罚），α 越大惩罚越重、权重被压得越狠。调 α 就是在"拟合准确"和"模型简洁"之间找平衡点。

配套仓库里把三种模型放进同一套交叉验证流程对比。有个细节值得说：所有模型都先做了标准化。

```python
def compare_regularization(X, y, alphas=(1.0, 10.0, 100.0)):
    """对比线性回归和不同 alpha 下的 Ridge/Lasso 的交叉验证 RMSE。
    所有线性模型都先标准化（正则化对特征尺度敏感）。
    """
    rows = [{
        "model": "linear", "alpha": None,
        "rmse": _rmse_cv(make_pipeline(StandardScaler(), LinearRegression()), X, y),
    }]
    for a in alphas:
        rows.append({
            "model": "ridge", "alpha": a,
            "rmse": _rmse_cv(make_pipeline(StandardScaler(), Ridge(alpha=a)), X, y),
        })
        rows.append({
            "model": "lasso", "alpha": a,
            "rmse": _rmse_cv(make_pipeline(StandardScaler(), Lasso(alpha=a, max_iter=10000)), X, y),
        })
    return pd.DataFrame(rows)
```

为什么必须标准化？因为惩罚项罚的是权重大小，而权重大小和特征的量纲直接挂钩。面积以"平方英尺"计（几千），房间数以"个"计（几个），不标准化的话，面积的权重天然就小、房间数的权重天然就大，正则化会不公平地偏向惩罚某些特征。标准化把所有特征拉到同一尺度，正则化才公平。这是用正则化时最容易忽略、却最致命的一步。

## 在真实房价数据上，正则化到底帮了多少

拿 Ames 房价数据跑一遍，用全部数值特征预测售价。结果比教科书说的要克制一些：

| 模型 | alpha | 交叉验证 RMSE |
|------|-------|--------------|
| 线性回归 | — | 36244 |
| Ridge | 10 | 36178 |
| Ridge | 100 | 35934 |
| Lasso | 100 | 36162 |

![正则化强度对回归RMSE的影响](regularization_rmse.png)

诚实地说，提升不大：Ridge 在 α=100 时把 RMSE 从 36244 降到 35934，改善约 1%。为什么不像教科书例子那样戏剧性？因为 Ames 数据的多重共线性是温和的——有相关的特征，但没到病态的程度。这恰恰是真实数据的常态：**正则化不是能让分数暴涨的魔法，它是一道保险，在共线性严重时救你，在共线性温和时也不会帮倒忙。**

真正能看出正则化在做什么的，是系数的变化轨迹：

![Ridge系数随alpha增大而收缩](coef_shrinkage.png)

这张图追踪了几个主要特征的系数随 α 变化的过程。α 很小时（左侧），系数各自为战，有的很大；随着 α 增大（向右），所有系数被稳步压向 0，但不会真的到 0——这就是 L2 收缩的典型形态。如果换成 Lasso，你会看到某些线在某个 α 之后直接贴着 0 走，那是 L1 把它们"选择性删除"了。

看懂这张图，就看懂了正则化的本质：它不是在改善预测的某个瞬间，而是在**约束模型的复杂度**，让系数维持在一个合理的量级，从而换来更稳定、更能泛化的模型。

## 什么时候用哪个

给个实战判断：

- **特征不多、就想要个稳健的基线** → Ridge。它温和地收缩所有系数，几乎不会帮倒忙，是默认的安全选择。
- **特征很多、怀疑大部分没用、想自动筛掉** → Lasso。它会把无用特征的系数压到 0，产出一个更简洁、更好解释的模型。
- **两者都想要** → ElasticNet（L1 + L2 的组合，sklearn 里也有现成的），这里不展开。

还有一个常被忽略的点：α 本身需要调。上面的表格手动试了几个值，实战中应该用交叉验证系统地搜最优 α——这正是下下篇要讲的调参。

这一篇的技术都是 sklearn 的标准组件，`Ridge`、`Lasso` 各一行就能调用。但真正的功夫在理解：线性回归的系数为什么会失控，惩罚项怎么把它拉回来，以及为什么用之前必须标准化。看懂这三点，正则化对你就不再是一个黑盒参数。
