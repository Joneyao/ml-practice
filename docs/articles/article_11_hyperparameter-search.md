# 机器学习实战 #11：调参的性价比，GridSearch、RandomSearch 还是贝叶斯优化

在电信流失数据上调随机森林，我用两种方式找最优超参数。

网格搜索：试遍 12 组组合，花了 23.9 秒，最佳 AUC 0.8436。
随机搜索：只试 6 组，花了 11.8 秒，最佳 AUC 0.8436。

一模一样的分数，随机搜索用了一半的候选、一半的时间。

调参不是"试得越多越好"，是一道性价比题。这一篇讲清楚网格搜索、随机搜索、贝叶斯优化这三种策略各自的逻辑，以及为什么大多数时候，随机搜索才是那个聪明的默认选择。

## 超参数：模型自己学不出来的那部分

先分清两种"参数"。

模型训练时自己学出来的叫**参数**——线性回归的权重、神经网络的连接强度，这些是数据喂进去、模型自己调出来的。

而**超参数**是你在训练开始前就得定死的设置——随机森林要种多少棵树（`n_estimators`）、每棵树最深几层（`max_depth`）、学习率多大。模型学不出这些，它们是你给模型定的"规矩"。超参数定得好不好，直接影响模型最终的表现。

问题是，超参数的最优值没有公式可算，只能试。试的方法，就分出了三种调参策略。

## 网格搜索：地毯式轰炸

最直接的想法：把每个超参数的候选值列出来，所有组合都试一遍，挑分数最高的。这就是网格搜索（Grid Search）。

比如 `n_estimators` 试 [50, 100, 200]、`max_depth` 试 [3, 5, 10, None]，组合起来就是 3×4 = 12 组，每组都用交叉验证打分。配套仓库里用 sklearn 的 `GridSearchCV` 实现：

```python
def run_grid_search(X, y, param_grid, seed=0):
    t0 = time.perf_counter()
    gs = GridSearchCV(RandomForestClassifier(random_state=seed), param_grid,
                      cv=_cv(seed), scoring="roc_auc")
    gs.fit(X, y)
    return {
        "best_params": gs.best_params_,
        "best_score": float(gs.best_score_),
        "n_candidates": len(gs.cv_results_["params"]),
        "elapsed_seconds": time.perf_counter() - t0,
    }
```

网格搜索的优点是彻底——给定的组合一个不漏。缺点是组合数会爆炸。两个超参数各 4 个候选是 16 组，五个超参数各 4 个候选就是 4⁵ = 1024 组，再乘上交叉验证的 5 折，等于训练 5120 次模型。超参数一多，网格搜索就贵得跑不动。这叫"维度灾难"：每加一个超参数，搜索空间翻好几倍。

## 随机搜索：为什么"少试"反而更划算

随机搜索（Random Search）换了个思路：不试遍所有组合，而是在超参数空间里随机抽 N 组来试。你定一个预算（比如只试 6 组），它就从各个超参数的取值范围里随机采样 6 组组合。

```python
def run_random_search(X, y, param_distributions, n_iter=10, seed=0):
    t0 = time.perf_counter()
    rs = RandomizedSearchCV(RandomForestClassifier(random_state=seed),
                            param_distributions, n_iter=n_iter, cv=_cv(seed),
                            scoring="roc_auc", random_state=seed)
    rs.fit(X, y)
    return {
        "best_params": rs.best_params_,
        "best_score": float(rs.best_score_),
        "n_candidates": n_iter,
        "elapsed_seconds": time.perf_counter() - t0,
    }
```

听起来像碰运气，但它背后有个很深的洞察：**在大多数问题里，只有少数几个超参数真正重要，其余的怎么调都差不多。** 网格搜索把预算平均分给了每个超参数的每个候选值，其中大量预算浪费在了"不重要的超参数"上。随机搜索不受网格约束，能在"重要超参数"的维度上采到更多样的值，用更少的尝试就撞上好区域。

![网格采样与随机采样在超参数空间的覆盖对比](grid_vs_random.png)

看这张对比图就明白了。同样是 9 次尝试，网格搜索（左）在"重要超参数"这个横轴上只覆盖了 3 个不同的值——因为 9 组被排成了 3×3 的格子，横轴被反复采样了 3 遍。而随机搜索（右）的 9 个点，横轴上是 9 个各不相同的值。如果真正影响结果的就是这个横轴，随机搜索显然探得更充分。这正是随机搜索用更少尝试反而不输网格的根本原因。

实测印证了这一点。同一个超参数空间，两种搜索的对比：

| 搜索方式 | 候选数 | 耗时 | 最佳 AUC |
|---------|--------|------|---------|
| 网格搜索 | 12 | 23.9s | 0.8436 |
| 随机搜索 | 6 | 11.8s | 0.8436 |

![网格搜索与随机搜索的性价比对比](search_tradeoff.png)

随机搜索用一半的候选、一半的时间，拿到了和网格搜索完全相同的最佳 AUC。在这个例子里，网格搜索多试的那 6 组，对最终结果毫无贡献——纯属浪费。

这不是说随机搜索永远赢。网格搜索小、候选空间也小的时候，地毯式轰炸没什么坏处。但只要超参数稍微多一点、或者取值范围稍微宽一点，随机搜索的性价比优势就会越来越明显。**一个实用的默认策略是：先用随机搜索快速探明好区域，如果还想精调，再在那个小区域里做一次密集的网格搜索。**

## 第三条路：贝叶斯优化

网格和随机都有个共同的"笨"：它们每次尝试都是独立的，试完一组，不会利用这组的结果去指导下一组该试哪里。相当于蒙着眼睛撒点。

贝叶斯优化（以 Optuna 为代表）就聪明在这里：它会根据已经试过的组合和得到的分数，建立一个"哪片区域可能更好"的概率模型，然后优先往有希望的区域采样。试得越多，它对搜索空间的理解越准，采样越聚焦。

三种策略放一起对比：

| 策略 | 怎么选下一组 | 适合场景 |
|------|-------------|---------|
| 网格搜索 | 遍历所有组合 | 超参数少、空间小、要求彻底 |
| 随机搜索 | 随机采样 | 大多数场景的默认选择，性价比高 |
| 贝叶斯优化 | 根据历史结果智能采样 | 单次训练很贵（如深度学习）、想用最少次数逼近最优 |

什么时候值得上贝叶斯优化？当每一次训练都很昂贵的时候——比如训练一个深度学习模型要几小时，你没法试几百组，这时候"每一次尝试都尽量有价值"就至关重要，贝叶斯优化的智能采样能帮你用几十次尝试逼近最优。但如果单次训练只要几秒（像这篇的随机森林），随机搜索多撒几个点的成本比贝叶斯建模的开销还低，没必要上重型工具。

本文的配套代码只实现了网格和随机两种（它们是 sklearn 内置的），Optuna 作为概念介绍——为一个"单次训练几秒"的玩具问题引入一个专门的优化框架，属于杀鸡用牛刀。知道它存在、知道它什么时候该用，就够了。

## 调参之前，先问一句值不值

最后提一个容易被调参狂热盖过的事实：**调参带来的提升，常常比你想象的小。**

这篇的随机森林，精调完 AUC 是 0.8436。而上一组文章里，没调过参的逻辑回归在同样数据上 AUC 是 0.845——调了半天参的随机森林，还没追上一个开箱即用的逻辑回归。

这不是说调参没用，而是说调参的收益有上限，且边际递减。一个合理的工作顺序是：先选对算法、做好特征工程、保证评估方式（交叉验证）可靠，这些的收益通常远大于调参；等这些都到位了，再花时间精调超参数，榨取最后那几个百分点。把顺序搞反——在一个特征没做好的模型上疯狂调参——是新手最常见的时间浪费。

说白了，调参是收尾的精装修，不是地基。地基没打好，装修得再精致也撑不起来。

这一篇的工具都是 sklearn 现成的，`GridSearchCV`、`RandomizedSearchCV` 各一行。真正的判断力在于：知道随机搜索通常比网格更划算，知道贝叶斯优化留给"训练很贵"的场景，更知道调参在整个流程里只是收尾的一环，别本末倒置。
